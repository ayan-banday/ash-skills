# Study

Ash learns by first principles, mental models and thinking tools, so he understands enough to experiment on his own. The full process lives in Shasta's rule files. This skill points at them; **the rule files win** if anything here disagrees.

## Find Shasta

- **On Ash's laptop:** `D:\Shasta`.
- **In a cloud session of the Shasta repo:** the repo root.
- **Anywhere else:** say Shasta isn't reachable from here, and stop.

Read `CLAUDE.md` at the Shasta root first. Write only inside Shasta, never into the project this session started in, unless Ash asks.

## Steps

1. **The evening, up to an approved learning brief:** follow `_rules\Menus and Learning Briefs.md`, after reading `_reference\Evening Example (Half Marathon).md`. Done when Ash says yes to the brief.
2. **The study page:** follow `_rules\Clusters.md`, after reading `_reference\Study Page Example (Your SaaS's Own Look).md`. Build the HTML straight from the approved brief, with no Markdown copy first. Done when the HTML passes the desktop and phone checks.
3. **After he studies:** Ash explains the key takeaways back in his own words, Claude points out the gaps, and one line goes in `study log.md`.

## The rule that matters most

**After each section, Ash can answer its question in two or three sentences of his own and do the first step today.** Each section runs six moves: the question made real, what happens, where the problem lies, the idea that fixes it, how it looks filled in, and how you'd set it up and run it. It closes with "The answer": the question answered in full, standing alone, with every line taught in the section above it. When Ash names no situation, pick the most likely one from his own work, set at the level he actually hits it. Details are in `_rules\Clusters.md`.

## The things that went wrong before

Each was fixed by a rule in those files. Check for them in every draft:
- **Named concepts in the menu** ("the loop", "grilling") instead of plain questions about a problem Ash would hit.
- **Clever headings** ("Two pictures to think with, and three rules that hold everywhere") instead of the brief's question or a plain label.
- **People's names in the teaching text** ("Adam Robinson says…") instead of the logic on its own, with names saved for Sources.
- **Terms and files used before they were explained** ("the answer goes in `decisions/T1.md`"), and parts that were true but didn't answer the section's question.
