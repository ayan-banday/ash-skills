# The grilling before a field map

A field map is a big build, so it gets its own grilling first (Ash, Oct 30 2026). Run it by Fuji's rule book, section 3: open with the outcome, show the ticket's title, Problem and progress block every round, say back in short plain bullets, ask with lettered options and the recommended one first, save once at the end. Lists shown to Ash hold 3 at most; nest after that.

## What has to be settled

1. **The outcome, in his words.** "What do you want to be able to do once you know this field?" The answer is judgment, not knowledge: he can look at work in this field, say what it does, what's wrong, and one better way, and brief Claude to build the right thing. Push until the outcome says what it changes in his work.
2. **The spine: one real project.** "Which project in your work would this field move most?" The problem map hangs off it. With no project, invent a realistic one and label it.
3. **What he already knows, per shelf.** Propose the field's shelves (see `book-shape.md`), then ask for each: works here already, uses it without knowing how it works, barely touched, never touched. This sets the light on each shelf and which shelves get suggested problems.
4. **How he learned a field before.** One question: "Where did you learn a field well, and what made it stick?" The answer sets the pattern the book copies (for Ash: real problems, masters' work, copy and improve).
5. **The first chapter's problem.** Propose it from the unlock order; let him change it.
6. **Sources.** "Who do you trust in this field, and who explains the why best?" Then the rule: pick the best source per question, never a ranked list.
7. **The look.** Only if this is a new kind of page: colours, inspirations, how much flair. For a Shasta book the default is `look.md`.

## Ready means

Ash said yes to the outcome, the spine, the shelves with their lights, the first chapter, and the sources. Set the ticket `ready`, save the decisions to its Answer, and start the build in its own session.

## Example, from the technology grilling

- Outcome: know the big parts of technology, so on Udyaan he knows which processes and technologies he can use, and what more problems he can solve.
- Spine: "Udyaan serves 10× the students with the same team, because software does most of the work."
- Shelves: making things people want to use (lit); where data lives and how it moves (faint); how software is built and kept running (faint); machines that learn and act (dim); keeping it safe and trusted (dark).
- First chapter: students hand in work on the site instead of Google Docs, because the dashboard, search and the agents all wait on it.
- Sources: Karpathy and Matt Pocock for AI philosophy, Greg Isenberg for the practical side of sites, CS50 for the basics, Lenny for product thinking.
